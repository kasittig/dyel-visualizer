# hooks/app

Hooks extracted from `App.tsx` (Phase 3 of the App Refactor migration, see root `HANDOFF.md`) that own top-level state and orchestration. `App.tsx` composes these three in sequence: `useAppSettings()` → `usePipelineOrchestration(...)` → `useVisualizerData(...)`.

| File                          | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `useAppSettings.ts`           | All settings state (`url`, `inputMode`, `pastedText`, `activeTab`, `deadliftStance` — localStorage-backed via `useLocalStorageState` — plus `dateRange`, `panelForcedOpen`, `refreshToken`, `shownResetToken`), the mount-time `?sheet=`/`?mode=`/`?text=` query-param → localStorage reconciliation, the URL-sync effect, the `athlete` memo, and the `handleUrlChange`/`handleTextChange`/`handleModeChange` handlers    |
| `usePipelineOrchestration.ts` | `(inputMode, url, pastedText, refreshToken, athlete) => { status, model, invalidUrl, textValidation }` — resolves raw input via `useResolvedRawInput`, builds the model via `@dyel/api`'s `buildPipelineModel`, owns the localStorage-persisted raw-data cache (keyed by sheet URL) for instant restore on revisit, and computes the effective status/model (falling back to cached data while a fresh fetch is in flight) |
| `useVisualizerData.ts`        | `(model, dateRange, deadliftStance) => { tabRows, visibleLiftIds, baselineCanonicals, targetCanonicals, dataUnit, volumeByDate, allSessionDates, lastSessionDate }` — all model-derived data via `@dyel/api` selectors (`groupByLiftType`, `defaultCanonicalsByLift`, `visibleLiftTypes`, `detectDataUnit`, `collectVolumeRecords`, `calculateVolumeCorrelationFromTagged`, `collectSessionDates`)                         |
