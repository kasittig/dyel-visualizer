# features/team-summary

Internal-preview leaderboard variant of `features/team-view/`, for comparing multiple lifters'
summary statistics (Squat/Bench/Deadlift/Total e1RMs, sessions, and most recent session details) in
a single always-visible sortable table — no exercise picker, no facet filters, no per-row overrides
(contrast with `features/team-view/`'s per-exercise comparison table). Linked from `/team` via a 🏆
"Summary view" link so users can compare both designs and give feedback before one replaces the
other. Like `features/team-view/`, it does NOT use `PipelineContext`/`usePipelineModel()` — it fans
out over MANY lifters' `PipelineModel`s simultaneously (one per row) via the shared
`useTeamViewData` hook (imported from `../team-view`, its owning feature, via that feature's
`index.ts` barrel — this feature has no data-fetching hook of its own). Since `useTeamViewData`
wraps its fetches in `teamCsvCache.ts`'s `cachedFetchSheetCsv`, this page inherits that caching for
free — navigating here from `/team` (or revisiting either page) reuses already-downloaded CSV text
instead of re-fetching the index sheet and every lifter's sheet again. The table is built from the
shared `Table`/`TableCard`/`TableHeadRow`/`TableRow`/`TableCell` primitives in
`shared/components/Table.tsx`, with page-local modifier classes (`cellTint`, `placeholderCell`)
layered on via `TableCell`'s `className` prop. Columns are sortable via the shared
`useSortableRows` hook, called directly in `TeamSummaryPage.tsx` — mirroring the same pattern
`AccessoryTable`/`DiagnosticsPanel`/`TeamViewPage` use.

| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

**Per-lifter deep-link:** Each row carries `url` (the lifter's Google Sheet URL, threaded straight through from `LifterPipelineResult.url` — present on both the `'success'` and `'error'` variants, so it's set for placeholder rows too). `TeamSummaryPage.tsx` renders a small "↗" link icon next to the lifter's name in the Lifter column, pointing to `` `${siteRootPath()}?sheet=${encodeURIComponent(row.url)}` `` with `target="_blank"` — this deep-links into the main DYEL Visualizer (`useAppSettings.ts`'s `sheet` query-param handling) pre-loaded with that lifter's data, opened in a new tab so the viewer doesn't lose their place in the summary table. The "← Back to DYEL Visualizer" link uses `siteRootPath()` the same way. See `features/team-view/CLAUDE.md`'s "Per-lifter sheet link" section for why this uses `siteRootPath()` (`shared/pageRouting.ts`) rather than a dot-relative `href="."`/`href="./..."`: the latter broke specifically for this page's two-segment `/team/summary` path, resolving one level too shallow and creating a navigation loop with `/team` instead of reaching the root visualizer.

**Placeholder rows:** `rows` always contains one entry per lifter in `results` (never omits a lifter), regardless of whether that lifter has data for the current date range or whether their sheet failed to load (`status: 'error'`). Lifters with no data (either due to a failed load or no logged sessions in the current date range) get a placeholder row (`hasData: false`, em-dash values for e1RMs, `0` for session count, and `'—'` for Last set/Date) so the viewer can see the full roster at a glance. `TeamSummaryPage.tsx` renders these with the muted `styles.placeholderCell` class.

**Session/Last set/Date redefinition:** Unlike `features/team-view/`, which scopes these fields to a single selected exercise, this page has no per-exercise selection, so `useTeamSummaryData` calls `buildMostRecentSessionDetail(model.tagged)` without a canonical filter, pulling the most recent session record across any lift type, then formats it via `formatLastSessionParts(sessionDetail, unit)` — yielding a generic "Last set" display like `"3x5 @ 225 lbs"` regardless of which exercise it came from. Session count (`sessionCount`) is derived by counting distinct dates in the lifter's `model.tagged` records within the current `dateRange`, again across all lifts.

**Date range + unit state ownership:** Like other feature-local state in this app, date range and unit are owned locally in `useTeamSummaryData`, not app-wide (`useAppSettings`) — this page's date range is independent of the main Visualizer's and of `features/team-view/`'s. `useTeamSummaryData` filters the e1RM data via `dateRangeToRenderParams` + `buildChartDatasets` (the same pipeline `TotalChart` uses), and counts sessions by filtering `model.tagged` records via `isRecordInDateRange`, ensuring consistency with the main app's date-range semantics.
