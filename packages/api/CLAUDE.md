# CLAUDE.md

`@dyel/api` should be the sole boundary between `packages/app` and `@dyel/pipeline`. App
components and hooks should never import `@dyel/pipeline` directly — only from `@dyel/api`.

## Convention

Most exported functions take pipeline-derived data (a `PipelineModel`, or a slice of one
like `TaggedSetRecord[]`) plus component-specific params (date range, display unit, etc.),
and return plain data — no React dependency in this package.

**Raw-input entry point exception:** `parseSheetData`/`parseTextData` take raw input (a CSV
string / pasted text) instead, because their job is to _produce_ a model in the first place —
they call `runPipelineModel` internally rather than receiving an already-computed one.

**Direct pipeline imports (engine-internal, not re-exported):** Several new `@dyel/api`
modules import pipeline compute engine internals directly rather than routing them through
`@dyel/api`'s own exports, because they are dataset/query primitives only used internally by
other API modules (never by external consumers). `buildDatasetsFromModel` (used in
`getCompetitionTotal.ts`) and `matches` (used in `conjugate/conjugateBestSet.ts`,
`session/lastSessionDetail.ts`, `variation/variationRadarSelectors.ts`) fall into this
category. Additional engine-internal normalization math is imported the same way:
`isSpeedWork`/`calcE1RM` (in `conjugate/conjugateBestSet.ts`), `normalizeE1rm` (in
`variation/variationSnapshot.ts`), and `invertE1RM`/`projectE1RMToDate` (in
`repCalculator/repCalculatorUtils.ts`).

**Pass-through re-export exception:** `classifyExerciseName` is re-exported from
`@dyel/pipeline` as a documented exception (see `validation/classifyExerciseName.ts`). It
wraps pipeline's internal `parseExercise` detector, which isn't part of pipeline's public
surface and cannot be safely duplicated outside `packages/pipeline` without duplicating the
detector engine itself — a high-drift-risk duplication that violates the "no re-exports"
rule for any other use case. Since `packages/app` needs `classifyExerciseName` directly in
validators, this minimal pass-through is the necessary exception, in the same category as
the raw-input entry points above (an unavoidable boundary-crossing for legitimate reasons).
